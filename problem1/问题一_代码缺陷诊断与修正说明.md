## 二、B1（根因）：边界顶点被浮点误差误杀

### 现象

| 案例 | 原代码输出 D | 正确 D | 原代码区域 | 正确区域 |
|---|---|---|---|---|
| case1 | 1.0034 m | **3.4921 m** | 三角形（顶点数 3） | 六边形（顶点数 6） |
| case2 | 3.4311 m | 3.4311 m | 四边形（4） | 四边形（4）✓（不受 B1 影响） |
| case3 | 0 m（退化为单点） | **3.4921 m** | 单点 | 四边形（4） |

### 机理

交会定位区域的每一个顶点，必然同时落在两条"约束边界射线"上，也就是说它**恰好取到约束的等号**：

```
angle(P - S_i) = theta_i ± 1°
```

代码用 `atan2d` 反算 `angle(P - S_i)`，结果会在 44.0° 上下抖动约 1e-13 度。
而 `point_in_sectors.m` 用的是

```matlab
if angle_to_P < theta_min || angle_to_P > theta_max   % 无任何容差
```

于是：算出来 43.999999999999 的点被保留，算出来 44.000000000001 的点被丢弃。
**保留/丢弃完全由浮点最后一两个比特决定，与几何无关。**

实测证据：把三个案例的全部有效顶点逐一检验，它们到最近约束边界的角距**全部为 0**。
把容差从 0 改为 1e-9°：

```
case1: 有效顶点 4 → 6   D 3.0146 → 3.4921
case3: 有效顶点 2 → 4   D 2.4258 → 3.4921   （2 个点已退化成线段）
case2: 不受影响
```

MATLAB 最终留下 3 个顶点、Python 移植版留下 4 个，正是同一"浮点抽签"在不同舍入下的不同结果。

### 修正

给 `point_in_sectors` 增加角度容差参数（默认 `1e-9` 度），并在 `main_problem1.m` 中传入：

```matlab
ang_tol = 1e-9;
if point_in_sectors(candidates(k,:), detectors, azimuths, angle_err, ang_tol)
```

### 更稳妥的做法（建议）

"射线求交 → 逐点筛选 → 求凸包"这条链路天然脆弱：它**依赖"区域顶点恰好是两条边界射线的交点"**，
一旦后续考虑有效接收半径截断（题目给出 1000~1500 m），区域边界会出现圆弧截断边，
该链路就**无法生成对应顶点**，问题二/三/四会继续出问题。

建议把定位区域直接按**半平面求交**（Sutherland–Hodgman）解析求出：
每个检测点的扇形约束 = 两个半平面之交集，`2n` 个半平面依次裁剪一个足够大的包围盒，
结果即为精确凸多边形。该方法：

- 顶点由裁剪直接产生，天然落在边界上，不需要事后筛选，**不存在浮点误杀**；
- 复杂度 O(n·v)（v 为当前多边形顶点数），与现有 `O(n^3)` 相比更优；
- 容易扩展到"再加一个半径圆约束"的后续问题。

本项目已提供 Python 参考实现：`verify_problem1.py`（仅标准库，可直接运行核对）。

## 三、B2：旋转卡壳实现不可靠

用 5000 个随机凸多边形与暴力枚举对照：

```
原版旋转卡壳 出错次数 = 38 / 5000  （约 0.8%）
修正版旋转卡壳 出错次数 = 0 / 5000
```

原版缺陷：
1. 推进 `j` 后只评估 `dist(V_i, V_j)`，**没有评估边的另一个端点 `V_{i+1}` 到 `V_j` 的距离**，
   遇到平行边（面积相等）会漏掉真正的直径端点；
2. 停止条件用"相邻边向量叉积"判断，与"面积最大"不等价。

修正版改为经典写法：对每条边把对踵顶点推进到面积最大，并同时评估边的两个端点。
注意本问题凸包顶点数 m 通常 ≤ 6，**直接暴力枚举 O(m²) 也能保证正确**，是更保险的选择。

- 覆盖圆：圆心 $(50.0000,50.0305)$，半径 $R=D/2=1.7460$ m

### 案例2　五检测点（$\pm1^\circ$，题面规定误差）

- 定位区域：4 顶点 `(100.0000,100.0000) (103.3742,99.9411) (103.4311,100.0000) (103.3742,100.0589)`

> **误差设定纠偏（2026-09-12）**：早期版本把本案例误差人为放大到 $\pm5^\circ$ 才"产生交集"
> （那时 $D=16.0900$ m），偏离了题面规定的 $\pm1^\circ$。实测 $\pm1^\circ$ 下五扇形同样有非空交
> 集，故已改回 $\pm1^\circ$，不再单独占一个算例。
>

### 案例3　两检测点

- 原稿称"定位区域退化为单点、$D=0$"——**错误**，那是 B1 缺陷造成的假象。

### 案例4　等边三检测点（新增，用于支撑"不能覆盖"的结论）

三个检测点位于半径 300 m 的等边三角形顶点，示向度均指向原点，$\pm1^\circ$：

- 定位区域：**六边形**
  ```
  (-5.9863, -0.0000)   (-3.0541, -5.2898)   (2.9931, -5.1843)
  ( 6.1082, -0.0000)   ( 2.9931,  5.1843)   (-3.0541,  5.2898)
  ```
- $D=12.0945$ m，$R=6.0472$ m
- $d_{\max}=6.1389$ m **> R**，超出 **0.091640 m（相对超出 1.5154%）**
- **覆盖性：不能覆盖** ✔

> 该相对超出量与布站半径无关（尺度不变）：$d_{\max}/R \equiv 1.015154$。
> 这恰好给出一个"同样 $\pm1^\circ$ 误差，结论却相反"的对照，
> 是说明"能否覆盖取决于区域几何形状、不能仅由直径判定"的关键证据。
>
> 对比：检测点若按**正四边形**（4 点）均匀布站，则 $d_{\max}/R = 1$ 恰好能覆盖；
> **正三角形**（3 点）、**正五边形**（5 点）则不能覆盖（$d_{\max}/R = 1.015154$ 和 $1.010265$）。
> 这个"奇数布站盖不住、偶数布站刚好盖住"的规律可直接写成论文里一个有说服力的段落。

误差统一 $\pm1^\circ$；剔除"区域无界"的配置），把**同一批输入**分别喂给两条链路：

- MATLAB：`verify_random_matlab.m`（射线求交 + 容差筛选 + 凸包 + 旋转卡壳，与主程序同源）
- Python：`verify_random_python.py`（半平面求交 + 暴力枚举直径，参考解）

首轮比对即暴露 **43/200 组分歧**，MATLAB 端全部报"退化"而 Python 端有正常解。
逐例调试（典型是 n=2 的第 2 组）后定位到**缺陷 B5**。

### B5 的机理

随机配置里检测点站位分散、示向度指向重心，于是**某个检测点常常正好落在其余所有扇形内**。
此时该检测点自身就是定位区域的一个顶点——它是自己那个楔形（$\theta_i\pm\varepsilon$ 张成的闭楔形）的**顶点**。

问题在于：从该检测点指向它自己的方位角在数学上**没有定义**，`atan2d(0,0)` 返回 0。
原 `point_in_sectors.m` 拿这个 0 去和该检测点的扇形区间比较，通常落在区间外，
于是判定"不在扇形内"，**把这个合法顶点丢掉了**。

后果是**直径被严重低估**。以随机集第 2 组为例：

| | 顶点数 | 直径 $D$ / m |
|---|---|---|
| 正确（含楔形顶点） | 3 | **95.5749** |
| 丢失楔形顶点后 | 2 | 25.98（且被误判为退化） |

案例2（主测试集）**侥幸没出错**：那个中心检测点的示向度恰好是 $0^\circ$，而
`atan2d(0,0)=0` 正好落在它的扇形 $[-1^\circ,1^\circ]$（即 $[359^\circ,1^\circ]$）内，
于是顶点被"碰巧"保留了下来。
换句话说，**原代码在这一点上的正确与否，取决于某个示向度是否恰好等于 $0^\circ$**。

### 修法

`point_in_sectors.m` 中，当待判点与该检测点重合（距离在数值容差内）时，
直接**跳过该检测点的角度判断**（闭楔形包含其顶点，该约束视为满足），其余检测点照常判断：

```matlab
if norm(vec) <= 1e-9 * max(1, norm(detectors(i, :)))
    continue;    % 该点即本检测点的楔形顶点，约束视为满足
end
```

修好后重跑：

| 指标 | 结果 |
|---|---|
| 直径 $D$ 不一致 | **0 / 200**（最大相对误差 $3.0\times10^{-9}$） |
| 凸包顶点数不一致 | **0 / 200** |
| 覆盖性判定不一致 | **0 / 200** |
| MATLAB 端误判"退化" | **0 / 200**（修复前 43 / 200） |

顶点数分布（两端完全一致）：顶点3 有 57 组、顶点4 有 132 组、顶点5 有 9 组、顶点6 有 2 组；
能覆盖 185 组、不能覆盖 15 组。

> **对论文的含义**：B5 只在"某检测点恰好落在交会区域内"时才起作用。真实题面中检测点位于
> 岸上、目标在 1000~1500 m 外，交会区域离检测点很远，**一般不会触发**。
> 但案例2 这种"中心布一个检测点"的构造会触发，因此必须修好，
> 否则该算例的结论依赖于示向度是否等于 $0^\circ$，一旦评审换个数就崩。

### 判定"能否覆盖"的两点说明

1. **直径端点不唯一时覆盖性会有歧义**。对称性强的区域可能存在多组等长对踵点对，
   取不同的一组当"直径"，$d_{\max}$ 会不同。本次比对中 200 组里两种取法（最好/最坏）
   的覆盖判定**完全一致**，说明本例无此歧义；但论文写"以直径端点连线为直径构造圆"时，
   最好补一句"若直径不唯一，取使 $d_{\max}$ 最大的那一组"，结论更稳妥。
2. **不要用蒙特卡洛代替解析判定**。采样最大点对距离必然 $\le D$（本次分别为
   $3.4524 / 3.3876 / 3.4303 / 11.9256$ m，均小于解析值），
   它只能佐证、不能作为覆盖性的判据。
